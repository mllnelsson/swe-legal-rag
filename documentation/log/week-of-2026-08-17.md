# Documentation Update Log — week of 2026-08-17

## 2026-08-22
* **Fix**: [Conversational agent](/retrieval/chat-agent.md) — the latency section named `read_decision` as the cost to watch. Trace records for two measured turns put the orchestrator's own loop iterations at 52% and 65% of a turn's wall clock and the reading sub-agent at 21% and 2%; a reading costs about six seconds, and what it really adds is the extra iteration needed to use its result.
* **Fix**: [Reading a decision](/retrieval/chat-agent.md#reading-a-decision-is-a-sub-agent) now selects passages instead of summarising them. `read_decision_text` returns a `ReadingSelection` (`relevance`, `chunk_indices`, `summary`) over the decision shown as numbered passages, and the text of each selected passage is fetched from the database by index rather than written by the model — closing the gap where the reader's own prose reached the synthesis step as unverifiable evidence. `ANSWER_SYNTHESIS` now states explicitly that a reading is guidance, never a source, the same status an annotation already had. See [ai package](/packages/ai.md) and [agents package](/packages/agents.md).
* **Update**: [`DecisionReading`](/packages/ai.md) carries `handles: list[str]` and `summary: str` in place of a single `extract` string — a deliberate shape change, not a bug, matching the reading path's move from writing prose to selecting passages.
* **Fix**: [`tool_loop`](/packages/llm-core.md) serialises non-string tool results with `json.dumps(..., ensure_ascii=False)`. Escaping every å, ä and ö to `\uXXXX` inflated a Swedish-heavy tool result by roughly half, and the inflated string was paid for again on every later loop iteration since it stays in history.
* **Update**: [LLM observability](/observability.md) records two gaps in what a trace can show: a tool's offered definitions are never captured, only which were called; and a loop's very last tool result is written into no record at all, since no later iteration exists to carry it forward as history — benign when the loop ends on a terminal tool, but a `MaxIterationsError` run loses that record. Also notes that `agents.chat.read` records now carry `operation: "generate_structured"`.
* **Update**: [Chat endpoint](/api/chat-endpoint.md) — a `sources` entry may now originate from a reading as well as a search; both feed the same handle assignment, so a passage never gets two handles for being found twice.
* **Update**: [llm-core](/packages/llm-core.md) — `tool_loop` is an async generator yielding `ToolCallStarted`/`ToolCallFinished`/`ToolLoopFinished` instead of taking `on_tool_call`/`on_tool_result`. The callbacks were awaited inside the loop and so could not `yield`, which is why the [conversational agent](/retrieval/chat-agent.md) ran the loop as a task pushing to a queue it drained; that machinery is gone and the agent is a plain `async for`. A generator cannot return a value, so the result travels as the final event, and `run_tool_loop` drains it for callers that want only that — the [SQL agent](/api/sql-agent.md) among them.
* **Update**: The [conversational agent](/retrieval/chat-agent.md) has one terminal tool. A turn needing no retrieval ends the way a tool loop ordinarily ends — the model calls nothing and writes the reply itself — so `reply_from_context`, `CHAT_DIRECT_REPLY`, `ai.reply_from_context` and the `answer.direct` label are gone from the [chat endpoint](/api/chat-endpoint.md) and a greeting emits no step frames. This closed a defect the extra tool had been hiding: the message from a no-tool ending was discarded, so a model that simply answered still reached the user as "Jag hittade inget i besluten". A greeting is now one billed call and one trace record rather than two — see [observability](/observability.md).
* **Update**: The [conversational agent](/retrieval/chat-agent.md)'s `answer` tool takes structured annotations — `{handle, carries, caution?}` plus a `gaps` list — in place of freeform `notes`. The synthesis prompt's rule that guidance is never a source stays; freeform prose had no enforceable line between "c3 carries the deadline rule" and "the deadline is three weeks", and structured fields have nowhere to put the second. `chunk_ids` was redundant once the annotations name their handles, and `document_ids` was written and never read.
* **Creation**: The answer marks each claim with the passage it rests on. [`ANSWER_SYNTHESIS`](/packages/ai.md) writes `[c3]` after the sentence it supports, [`event: sources`](/api/chat-endpoint.md#event-sources) carries a `handle` and is now one entry per **passage** rather than per decision, and the client resolves the two into a numbered superscript. Deduplicating by decision would have left a marker pointing at nothing.
* **Update**: [Chat endpoint](/api/chat-endpoint.md) — `sources` is now emitted **before** the token stream on every path, where it used to follow it. The selection is fixed the moment `answer` runs, so this is both the order that lets a citation marker resolve as it arrives and the truthful one: the evidence was chosen before the prose was written. This deliberately changes [honesty rule 17](/frontend/honesty-rules.md), whose second clause said sources are not rendered until the frame carrying them has arrived; the writing marker is what says an answer is unfinished, and `received` still gates rendering.
* **Creation**: [Honesty rule 22](/frontend/honesty-rules.md) — an inline citation resolves to a passage the reader can see, and a marker that cannot be resolved is removed rather than shown raw. That covers a handle the model never selected and a reopened conversation, which keeps the prose and not the citations. Rule 13 is extended to the inline component, since a superscript pointing at an appendix passage must not let a reader take it for the nämnd's reasoning. Twenty-two rules now, also reflected in [testing strategy](/testing.md).
* **Update**: [Chat endpoint](/api/chat-endpoint.md) — the `search.refused` label is gone. A declined filter was reported twice, by a label and by `status`, and the client's Swedish for the two running states was already identical; a `tool_result` now always carries the label its call did, and `status` alone distinguishes ok from refused from error. [Honesty rule 16](/frontend/honesty-rules.md) was always about the status and now says so.
* **Fix**: The [conversational agent](/retrieval/chat-agent.md)'s `list_vocabulary` advertised legal-concept values in its own description and never returned any — `DocumentFacets` carries no `concepts` field, so a bare call answered with an empty list that reads as "the corpus has none" rather than "you have not asked yet". It now returns a `concepts_note` saying concepts need a `contains` lookup, and both descriptions say so.
* **Fix**: [`ANSWER_SYNTHESIS`](/packages/ai.md) asks for plain text — no headings, no markdown, no bullet lists. The [frontend](/frontend/overview.md) renders the answer as text and always has, so the `##` and `**` the model was emitting reached the reader as characters; the rule the client's own code cited had never been in the prompt.
* **Fix**: [Health endpoint](/api/healthz.md) and [frontend](/frontend/overview.md) had `description` values containing `: ` unquoted, so their frontmatter did not parse — a conformance rule the bundle states as hard. Both are quoted.

## 2026-08-19
* **Update**: [Local Development Environment](/playbooks/local-dev.md) — Postgres moved to `pgvector/pgvector:pg17` (PG 17.11, pgvector 0.8.6). The previous `ankane/pgvector` is abandoned upstream and its `latest` is frozen at PG 15.4 / pgvector 0.5.1, so the documented "Postgres 17, pgvector 0.8.5" had never been what the Linux path actually ran. The approved-image table now pins the tag.
* **Update**: [Local Development Environment](/playbooks/local-dev.md) — the coding agent's sandbox section is now true on a host with no Postgres client. `db-sandbox.sh` runs the client tools through `docker compose exec -T db` when they are not on `PATH`, instead of exiting 0 in silence and leaving the session with no sandbox at all; `db-guard.sh` unwraps `docker exec` / `docker compose exec`/`run` / `sh -c` wrappers, which on a container-only host are the only way a write can reach `overklagan`. Records the rule that makes the unwrapping safe: the host environment does not follow a command into a container, so a container command naming no database resolves to unknown — protected — rather than to the sandbox that host `PGDATABASE` names.

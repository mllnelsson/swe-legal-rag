# Documentation Update Log — week of 2026-08-24

## 2026-08-27

* **Update**: [Local dev](/playbooks/local-dev.md), [Frontend](/frontend/overview.md),
  [live testing](/playbooks/live-testing.md) and [LLM
  Observability](/observability.md) — the documented dev-server command scopes
  `uvicorn --reload` with `--reload-dir packages`, so the reloader watches only
  first-party source and not `data/llm-traces/`, where every LLM/embedding call
  writes a trace file.
* **Update**: [Frontend](/frontend/overview.md) and [query
  expansion](/retrieval/query-expansion.md) — the results page's filters move
  into a single collapsed "Filter" disclosure above a one-column results page,
  replacing the always-open left rail; the home page gains a "Smart sökning"
  switch, its own entry point to query expansion, shown only in search mode
  beside a larger Sök/Agent mode switch.
* **Update**: [The conversational agent](/retrieval/chat-agent.md) gains a plan
  step ahead of its tool loop: a one-call `CHAT_PLAN` prompt on the strong
  `chat` model reads the question once and either replies directly — a
  greeting, a follow-up the history already answers — or hands a short English
  plan to the executor by calling `begin_research`. The executor's tool loop,
  carrying that plan, now runs on a new `orchestrate` role
  (`openai/gpt-oss-120b`) instead of `chat`, so the strong model plans and
  writes prose while the mechanical tool-calling runs on a cheaper one. See
  [LLM configuration](/reference/llm-config.md), [the chat
  endpoint](/api/chat-endpoint.md) (updated latency shape), [LLM
  Observability](/observability.md) (new `agents.chat.plan` trace source),
  [agents](/packages/agents.md), [ai](/packages/ai.md) (new `CHAT_PLAN`
  template), [api](/packages/api.md), [live testing](/playbooks/live-testing.md)
  and [the model-selection decision](/decisions/llm-model-selection.md).
* **Update**: [LLM configuration](/reference/llm-config.md), [ai](/packages/ai.md),
  [LLM pricing](/reference/llm-pricing.md), [cost estimate](/reference/cost-estimate.md),
  [the model-selection decision](/decisions/llm-model-selection.md) and [the SQL
  agent decision](/decisions/sql-agent.md) — `roles.read` and `roles.sql` move
  to `openai/gpt-oss-120b` and `roles.summarize` to `google/gemma-4-31B-it`.

  follow the chat's calmer presentation: the SQL lineage is reachable behind a

## 2026-08-25

* **Update**: [llm-core](/packages/llm-core.md) and [the chat endpoint](/api/chat-endpoint.md) —
  `tool_loop` binds a call's arguments before invoking, and a call naming an
  argument the executor does not have comes back as an ordinary `refused` tool
  result, spelling out the tool's valid arguments, rather than raising and
  ending the turn.
* **Update**: [ai](/packages/ai.md), [the conversational agent](/retrieval/chat-agent.md)
  and [agents](/packages/agents.md) — the `{tools}` block in the `CHAT_ORCHESTRATION`
  and `TEXT_TO_SQL` user prompts is generated by `render_tool_index` from the same
  `ToolDefinition`s the loop executes against, closing a drift between the
  hand-written prompt list and the real tool schemas.
* **Update**: [ai](/packages/ai.md) — `ai.tokenization` raises
  `TokenizerUnavailableError` naming the model when `transformers` cannot resolve
  one, instead of a later unrelated `AttributeError`.
* **Update**: [Application Logging](/logging.md) is cross-linked from [LLM
  Observability](/observability.md)'s "deliberately not captured" list, with the
  split stated: a log line carries only a 120-character preview of any text,
  a trace record carries the call whole, and both correlate on
  `interaction_id`.
* **Update**: [api](/packages/api.md) — `api/access_log.py` and
  `api/logging_setup.py`, `correlation.interaction_id_of()`, the lifespan's
  per-stage timing (with the embedding provider's own ~9s/~90s figure), and
  the chat route's `db.commit()` right after `get_or_create_session`, closing
  a reload race where a client could refetch a session the original request
  had not yet committed.
* **Update**: [Frontend](/frontend/overview.md) catches up with the merged UI:
  the home page's switch and inline keyword caption, the router-state question
  handover, the progress card that folds once the answer starts, the
  conversation panel that replaced the always-visible rail, and the
  app-wide `ErrorBoundary`. [Live testing](/playbooks/live-testing.md) and
  [sessions](/data-model/sessions.md) already reflected these; [architecture](/architecture.md),
  [indexes](/data-model/indexes.md) and [the sessions endpoint](/api/sessions.md)
  are corrected from "rail" to the panel that replaced it.
